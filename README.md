# CS-405 Secure Coding

## Overview

This repository contains work completed for **CS 405: Secure Coding** at Southern New Hampshire University. The course focused on identifying software vulnerabilities, applying secure coding standards, evaluating security risks, and incorporating security throughout the software development process.

Throughout the course, I worked with C++ and other supporting tools to examine common vulnerabilities and apply secure coding practices. The projects and activities in this repository demonstrate my understanding of concepts such as input validation, buffer overflows, SQL injection, numeric errors, exception handling, encryption, static code analysis, risk assessment, defense in depth, and zero trust.

## Repository Contents

### Project One – Security Policy

`Project 1.docx`

Project One focuses on the development of a security policy based on secure coding standards and industry best practices. The project addresses how security policies can help organizations establish consistent expectations for developing and maintaining secure software.

Project Two brings together concepts covered throughout the course and demonstrates how secure coding practices can be incorporated into the software development life cycle. ## Secure Coding Practices

Some of the major secure coding practices demonstrated throughout this repository include:

* Input validation
* Least-privilege access
* Defense in depth
* Secure exception and error handling
* Protection against buffer overflow
* Protection against SQL injection
* Numeric range checking
* Encryption of sensitive information
* Static code analysis
* Risk assessment and vulnerability mitigation
* Zero-trust security principles
* Incorporating security throughout the development life cycle

## Reflection

One of my biggest takeaways from CS 405 is that security should not be treated as a final step in software development. A program can function correctly and still contain vulnerabilities that place users, data, and systems at risk. Secure development requires thinking about potential threats from the beginning and continuing to evaluate security throughout design, implementation, testing, and maintenance.

This course strengthened my understanding of the responsibility developers have when creating software. I now approach development by considering not only whether the code works, but also how it could be misused, what vulnerabilities might exist, and what protections can be implemented to reduce those risks.
